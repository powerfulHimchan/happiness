# GP-217–226 · 검·활 장비10종

정예 보상에 검5종·활5종을 추가한다. 새로운 무기 종류나 공격 동작이 아니라 기존 검·활의 장비 설계다. 시작 장비는 그대로이며 실제 보상을 확정한 뒤에만 해당 도전에 적용된다.

| 작업 | 장비 | 고유 효과 | 희귀 무기 피해 / 고유 | 영웅 무기 피해 / 고유 |
|---|---|---|---|---|
| GP-217 | 결투 검 | 기본 공격 | +5% / +20% | +10% / +35% |
| GP-218 | 사냥 활 | 기본 공격 | +5% / +20% | +10% / +35% |
| GP-219 | 룬 검 | 스킬 | +5% / +20% | +10% / +35% |
| GP-220 | 주문 활 | 스킬 | +5% / +20% | +10% / +35% |
| GP-221 | 연무 검 | 기본 공격 | +10% / +15% | +20% / +25% |
| GP-222 | 정밀 활 | 스킬 | +10% / +15% | +20% / +25% |
| GP-223 | 단련 검 | 스킬 | +20% / +5% | +40% / +10% |
| GP-224 | 견고한 활 | 기본 공격 | +20% / +5% | +40% / +10% |
| GP-225 | 균형 검 | 기본 공격 | +25% / +0% | +45% / +5% |
| GP-226 | 균형 활 | 스킬 | +25% / +0% | +45% / +5% |

무기 피해 보너스는 해당 무기의 기본 공격·스킬에 적용한다. 고유 보너스는 표의 공격 종류에 합산한다. 보조 무기의 고유 보너스50%도 같은 공격 종류에 합산하며 마지막에 정수 반올림한다. 이진 소수 계산 오차만 최종 반올림 직전에 정리해 피해102.5를103으로 처리한다. 장비 보너스는 필살기에 적용하지 않는다. 예를 들어 영웅 주문 활은 활 스킬에+45%, 활 기본 공격에+10%, 보조로 보유하면 검 스킬에+17.5%를 제공한다. 균형 장비는 일반 피해를 높이고 보조 특화를 낮추는 선택지다.

## 획득과 표시

- 첫 정예는 희귀, 두 번째 이후 정예는 영웅 장비를 제공한다. 신규10종은 영구 해금 없이 후보에 등장한다. 태엽 검·활은 기존 보스 파괴 해금을 유지한다.
- 보상 첫 페이지에는 기존 검·활과 해금된 태엽 장비만 표시한다. 신규10종은 다음 세 페이지에4·4·2개로 표시한다. 페이지를 바꾸면 선택을 해제하고, 첫/마지막 경계 입력은 현재 선택을 보존한다.
- 전체 후보를 비교하거나 선택만 하는 동안은 저장·장비·체력·게이지가 바뀌지 않는다. 확정/현재 무기 유지 중 하나만 보상을 소비한다. 같은 등급의 다른 설계로 교체할 수 있으나 등급 하향은 거부한다.
- 대장간 무기 도감은 기존10개 순서 뒤 신규 희귀·영웅20개를 붙여 총30개, 세 카드씩10페이지로 제공한다. 기존 설계도 시설 카드와 해금 기록은 그대로다.
- 보조 효과의 HUD 문구는 장비의 실제 기본/스킬 특화를 사용한다. 현재 도전 상태에도 실제 합산 피해와 장착 설계를 표시한다.

## 저장과 검증

기존 `weapons.blueprints`의 검·활별 설계 ID를 사용하며 저장 형식은 바꾸지 않는다. 이름만 등록된 알 수 없는 설계, 다른 무기의 설계, 일반 등급 특수 장비를 거부한다. 저장 실패는 장비·대기시간·보상 확정을 롤백하고 기존 정상 저장을 보호한다. 이어하기는 저장된 설계/등급을 복원하며 새 도전은 기본 장비로 초기화한다.

신규 실행 검사31개는10종 각각의 실제 희귀 획득·저장 실패/재시도, 별도 프로세스 반복 복원·영웅 승급, 검 실제 타격/활 실제 투사체·보조 종류와 최종 반올림·필살기 제외, 5스테이지 완주·초기화를 포함한다. 보상 페이지는16:9/20:9 입력 안전 영역·겹침·조회 무변경을 검사한다. 추가 도감 검사는 기존10개 순서, 전체30개 성능·페이지, 기존2후보 API를 확인한다. 기존 GP-137 검사는 전체30개 도감과225개 검·활 조합으로 확장했다.

전체 검사는 기존465개+신규31개, 총496개 실행 단계와 Android 리소스 내보내기/패키지 부팅을 사용한다. 실기기 조작감과 새 장비 밸런스는 별도 확인 대상이다. APK는 명시적인 요청 시에만 생성한다.
