# GP-318 · 도착 엔딩과 영구 엔딩 기록

## 동작

- 새 전체 여정의 세라 선택 → 행복의 심장 입구 → `도착 · 이름 없는 행복` 3페이지 → 엔딩 기록 → 결과로 연결한다. 주민들에게 주인공의 이름이 없다는 첫 엔딩을 보여주며, 구출한 세라가 기억하는 약속과 파괴 후 홀로 기억하는 선택을 구분한다.
- 엔딩 대기 중 전투·시간·체력·재사용을 정지한다. 마지막 확인과 건너뛰기는 모두 기록 후 완료한다. 이야기 꺼짐은 장면 없이 같은 엔딩을 기록한다.
- 기억 수첩에 `엔딩` 탭을 추가한다. 미발견 내용은 잠그고, 발견 후 첫 주인공의 도착 이야기를 다시 읽는다. 최초 발견과 도전별 주인공·선택을 독립 보존하며, 도전 기록 삭제·새 도전으로 지워지지 않는다.
- GDD의 첫 엔딩 이후 진 최종 보스 순서를 따른다. 행복의 심장 전투와 귀환·해방·새벽 엔딩은 후속 범위다.

## 저장과 복구

- 기존 저장 버전1에서 선택 필드 `stage.arrival_ending`을 사용한다. 새 전체 여정은 `locked`, 심장 입구 확인 후 `pending`, 엔딩 확인 후 `seen`이다. 이야기 꺼짐은 세라 선택 확정 때 `seen`으로 기록한다.
- 대기 저장을 이어하면 첫 페이지로 돌아오며 기존 선택·체력·필살기·재사용을 복원한다. 엔딩 확인 저장 실패는 상태를 되돌리고 정상 파일을 지킨다. 영구 기록 실패는 확인한 체크포인트를 유지해 같은 버튼 또는 재실행으로 재시도한다.
- 엔딩 이벤트는 체크섬 저널에 기록한다. 같은 도전 재시도는 중복을 만들지 않고, 같은 도전의 다른 주인공·선택 덮어쓰기는 거부한다. 손상·미지원 이벤트를 건너뛰고 다음 정상 이벤트를 복구한다.
- 필드가 없는 GP-317 이전 저장은 기존 완료 흐름을 유지하며 엔딩을 소급 해금하지 않는다. 일반3/5스테이지와 지역 순회는 기존 흐름을 유지한다.

## 검증 범위

- GP-318 신규42개 실행 단계: 주인공2 × 무기2 × 선택2의 별도 프로세스 생성·복원·완료24개, 선택별 확인 저장 실패·영구 기록 실패·실패 후 재실행2단계·변조·이전 저장·이야기 꺼짐·저널·배치18개.
- 실제 엔딩 확인/건너뛰기와 수첩 탭 터치, 기록 초기화 후 보존, 16:9·20:9 배치를 검사한다. 기존 GP-315–317 완료 검사와 이전 저장 fixtures를 새 흐름에 맞춰 검증한다.
- PR 전체 Godot 검사와 Android 리소스 내보내기·패키지 부팅을 통과해야 병합한다. 요청받은 APK는 병합한 main에서 수동 빌드하고 SHA-256과 서명을 확인한다. 이번 엔딩의 Android 실기기 플레이 확인은 별도다.
