## 발견·칭호·호환

- 능력을 실제 선택해 기록한 기존 영구 발견 장부가 기준이다. 도감 열람·후보 노출·능력 등급 반복 선택은 수집 수를 늘리지 않는다. 무기 연구는 해당 계열만 센다. 없는 ID와 true가 아닌 값은 제외한다.
- 지상/공중 연구는 지정한 두 능력을 모두 발견해야 한다. 숙련5종·전술6종은 서로 배제되는 가지도 포함하며, **여러 도전에 걸친 영구 발견**으로 달성한다. 한 도전에서 배제 규칙을 풀거나 능력을 소급 지급하지 않는다.
- 기존 발견 기록은 시작 시 자동 반영한다. 기존 업적50개의 ID·티켓·진행·칭호를 유지하며 이전 버전1 장부도 그대로 읽는다. 각 신규 목표도 같은 최대값 누적·중복 방지·체크섬·손상 행 무시 규칙을 사용한다.
- 업적 장부 실패는 실제 능력 발견 저장을 막지 않는다. 실패한 업적은 재시도할 때 발견 장부에서 다시 계산한다. 빈 필터의 안내 카드를 눌러도 진행 기록을 재시도할 수 있으며 칭호는 임의 장착하지 않는다. 칭호 저장 실패 시 기존 선택을 유지한다.
- 칭호는 표시 보상이다. 체력·피해·보급전·체크포인트에 영향을 주지 않으며 새 도전·진단 기록 삭제 후에도 유지한다.

## 업적 화면

- 광장 기록 → 영구 업적에서 필터·분류·정렬 버튼을 눌러 순환한다. 필터와 분류를 함께 적용한 뒤 정렬하고 세 장씩 표시한다. 전체·목록순이 기본이다.
- 추천은 장착 중인 칭호를 먼저, 그 다음 미달성 목표를 진행률순으로, 달성 목표를 마지막에 놓는다. 진행률은 현재값/목표값이다. 동률은 ID로 고정한다.
- 조회 조건을 바꾸면 첫 페이지로 이동하고 범위를 벗어난 페이지는 보정한다. 일치하는 업적이 없으면 안내 카드와1/1페이지를 표시한다. 탭 재진입·마을 재진입 시 조회 조건을 초기화한다.
- 요약의 달성/미달성은 전체92개 기준, 표시는 현재 필터와 분류 기준이다. 시작 화면도 전체 업적 수를 동적으로 표시한다.
- 조회와 페이지 이동은 장부를 쓰지 않고 도전 상태를 바꾸지 않는다. 선택한 칭호가 다른 분류에 있어도 그대로 유지한다. 칭호 해제 후 장착 필터는 빈 안내로 바뀐다.

## 검증

- Godot4.7.2의 전용 검사에서42개 목표의 정확한 조건 충족·각 조건 미달·다른 계열/알 수 없는 발견 제외를 확인했다. 목표마다 실제 영구 장부에 부분 진행→완료→칭호를 기록하고 별도 프로세스에서 복원했으며 중복 기록과 진행도 감소를 차단했다.
- 로안·루미 양쪽에서 실제 발견 콜백으로42개 목표를 각각 완료하고 칭호 저장·장착 필터에서 실제 터치 해제·새 도전 보존을 확인했다. 업적 저장 실패 후 빈 필터 안내 카드 재시도와 칭호 미장착도 검사했다.
- 이전 형식 장부의 원본 바이트·기존 칭호·더 큰 이전 진행도를 보존한 채 신규 목표를 추가하고 별도 실행에서 다시 읽는 검사를 통과했다.
- 네 화면비1280×720·1600×720·1280×800·2400×1080에서 필터4종×분류14종×정렬4종의 실제 터치와 독립 조건 검사를 수행했다. 안전 영역·버튼 비중첩·페이지 상하한·빈 목록·재진입 초기화·조회 중 전투/저장 상태 보존을 포함한다.
- 기존 업적 검사6흐름을 다시 통과했다. 원래50개 ID와 티켓을 유지하면서92개 전체 카드의 실제 칭호 선택·해제·페이지 이동·별도 복원·저장 실패·손상 장부 복구를 확인했다.
- 실제 렌더러로 연구·장착·빈 분류·추천·공용 연구5상태×세 화면비의15화면을 생성해 한글과 배치를 확인했다. 정적 프로젝트 검사와 `git diff --check`도 통과했다.
- `scripts/check_godot_project.sh`의 전체 통합 검사를8묶음으로 나누어 실행했고 모두 종료 코드0으로 통과했다. 기존 이동·전투·직업·무기/스킬·과제·보급소·지역·보스·이야기·엔딩·원정·도감·저장/이어하기와 Android 리소스 팩 내보내기·팩 부팅을 포함한다. 신규 검사도 CI 목록에 등록했다. Android 실기기 플레이와 체감 밸런스는 미확인이다. 이번 요청에서는 APK를 생성하지 않는다.
