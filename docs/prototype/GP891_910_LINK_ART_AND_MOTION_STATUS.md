# GP-891–910 · 연계 그래픽10종과 애니메이션10개

최근 추가한 전투 연계42종에 문양과 표시 상태를 연결하고, 실제 발동·만료를 알아볼 수 있는 표시 전용 애니메이션을 추가했다. 기존 대기·이동·검/활 전신 원화와 공격/회피 동작은 유지한다.

## 표시 시계와 수명

`CombatLinkFeedback`은 이미 성공한 `combat_links` 잔여 시간만 읽는다. 무효 입력이나 차단된 타격의 예약 상태가 노출되지 않도록 플레이어의 실제 시각 갱신 경계에서 관찰한다. 같은 종류의 두 무기 발동은 하나로 모아 최대6문양·6효과로 제한한다. 같은 종류가 새로 발동하면 기존 효과를 갱신하며 화면을 무제한 채우지 않는다.

발동 효과는460ms, 만료 효과는320ms 안에 정리한다. 전투 문양은 주인공 머리 위에 배치하고 기존 방벽·직업 문장과 위치를 분리했다. 입자 위치는 고정 수식으로 계산하며 치명타 난수나 전투 신호를 만들지 않는다. 두 무기의 같은 종류 중 하나만 만료되면 표시를 유지하고 마지막 효과가 끝날 때만 만료 애니메이션을 재생한다.

사망·낙하 복귀 중에는 표시를 정리한다. 스테이지 이동·이어하기는 현재 잔량을 기준으로 표시를 초기화하여 이미 발동한 효과를 다시 재생하지 않는다. 전투 일시정지는 표시 시계도 정지한다.

`CombatLinksMenuMotion`은 전투 시계와 분리되어 일시정지된 상태 화면에서 선택/페이지 애니메이션만 재생한다. 페이지는200ms, 선택은260ms 안에 정착한다. 전환 중에는 매 프레임을 다시 그리고 마지막 정착 프레임도 요청한다. 앱 비활성화는 메뉴 표시 시계도 멈추며 닫힌 메뉴의 시계는 진행하지 않는다. 피해·성장·연계 잔량·입력 판정·저장 형식은 변경하지 않는다.

## 검증

신규 `gp891_910_presentation_runtime_test.gd`는 다음을 확인한다.

- 10개 SVG의 실제 가져오기·서로 다른 이미지 내용·아이콘 투명 모서리·카드 영역 비중첩·실제 상태별 프레임 선택.
- 6가지 발동 동작·동일 프레임 재호출·재발동 합치기·만료 정리·종료 임박 호흡·30/60/120Hz 일관성·다중 타격의 할당 상한.
- 두 주인공의 실제 표시 연결, 전후 피해/잔량/저장 스냅샷/치명타 난수/충돌체 불변과 스테이지 이동 시 재생 방지.
- 실제 메뉴 열기/카드/페이지/필터 터치, 전투 일시정지 중 표시 진행, 앱 중단 시 정지와 정상 복귀.

확인 결과: headless318개 assertion, 실제 OpenGL 렌더 실행403개 assertion을 통과했다. 렌더 결과는 세 비율(1280×720·1600×720·1280×800)의 상태/페이지18장, 메뉴 전환14프레임, 로안/루미 전투 표시52프레임으로 총84장이다. 발동/대기/미획득 화면은 상태별 표시 스냅샷을 사용하며, 실제 전투 수치와 저장 불변은 별도 런타임 검사에서 확인한다.

기존 연계 전투169개·UI965개·저장/이어하기53개 assertion, 주인공 상태 UI671개, 최근 주인공 애니메이션612개 및 검/활 전투 애니메이션 검사를 통과했다. 정적 프로젝트 검사와 Android 리소스 내보내기/패키지 부팅도 통과했다. 전체 전투 조합 재검사나 Android 실기기 플레이를 수행했다는 의미는 아니다. APK는 생성하지 않는다.

```bash
godot --headless --path game --script res://tests/gp891_910_presentation_runtime_test.gd -- runtime
# 실제 디스플레이/Xvfb에서 그래픽과 연속 프레임84장 출력
LINK_ART_RENDER_DIR=/tmp/link-art-gallery godot --path game --rendering-method gl_compatibility --audio-driver Dummy --script res://tests/gp891_910_presentation_runtime_test.gd -- render
```

신규 검사·전용 스크립트·SVG10개를 기존 자동 Godot 검사에 추가했다.
