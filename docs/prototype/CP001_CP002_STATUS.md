CP-102 첫 실기기 빌드에서 카메라 이동은 정상이지만 절차형 캐릭터가 보이지 않는 문제가 확인됐다. 캐릭터를 명시적 SVG 스프라이트로 교체하고 월드 내 표시 순서를 높였으며, 시작 지점을 조작 패드와 겹치지 않는 화면 중앙으로 옮겼다.

후속 실기기 확인에서 이동 속도와 방향 값은 반전되지만 캐릭터 시선이 오른쪽에 고정되는 문제가 확인됐다. 부모 노드의 음수 X 스케일 대신 `Sprite2D.flip_h`를 직접 제어해 왼쪽 입력에서는 캐릭터 그림을 수평 반전하고, 오른쪽 입력과 테스트 초기화에서는 원래 방향으로 복원하도록 수정했다.

첫 시선 수정 후에도 가상패드의 중간 세기 입력에서 시선이 갱신되지 않는 문제가 남았다. 원인은 `-1.0~1.0` 범위의 소수 입력을 정수용 `signi()`로 판정해 `-0.7` 같은 값이 `0`이 되는 것이었다. 방향 판정을 부동소수점용 `signf()` 기반 공통 함수로 통일해 패드 입력 세기와 관계없이 좌우 시선이 즉시 갱신되도록 수정했다.

CP-102는 실기기에서 이동, 감속과 좌우 시선 전환이 정상 동작함을 확인했다. CP-103에서는 최대 약 2.2m의 1단 점프, 버튼을 일찍 뗐을 때의 상승 속도 절단, 0.10초 코요테 타임과 0.12초 착지 입력 버퍼를 추가했다. 높은 연습 발판과 HUD의 점프 상태·높이·보정 유형 표시로 두 입력 보정을 재현할 수 있다.

CP-103은 실기기에서 가변 점프와 두 입력 보정이 정상 동작함을 확인했다. CP-104에서는 9.0m/s 지상 회피와 0.18초 무적, 패드 방향을 따르는 9.5m/s 공중 대시를 추가했다. 공중 대시는 착지 전 한 번만 사용할 수 있고 착지 시 복구된다. HUD에는 무적 시작·종료 물리 프레임과 사용 횟수를 표시한다.

CP-104는 실기기에서 지상 회피와 공중 대시가 정상 동작함을 확인했다. CP-105에서는 트랙을 두 구간으로 나눠 실제 낙하 구역을 만들고, 낙하 시 최대 체력의 10%를 차감한 뒤 약 0.45초 후 마지막 안전 지점으로 복귀하도록 구현했다. 안전 지점은 명시된 평지와 발판 영역에서만 갱신되므로 낙하 구역이 복귀 지점으로 저장되지 않는다.

CP-105는 실기기에서 낙하 피해와 안전 지점 복귀가 정상 동작함을 확인했다. CP-201에서는 플레이어가 바라보는 전방과 검 사거리 1.6m 안의 최근접 표적을 0.10초마다 찾는다. 현재 대상이 유효한 동안에는 새 후보가 20퍼센트 이상 가까워져야만 전환하며, 선택 대상에는 흰 외곽선과 작은 표식을 표시한다.

CP-201 첫 빌드에서는 탐색 수치와 HUD 로그는 바뀌지만 절차형 표적이 기기 화면에 보이지 않는 문제가 있었다. 표적 몸체와 선택 표식을 명시적 SVG 스프라이트로 교체한 뒤 실기기에서 정상 표시를 확인했다. CP-202에서는 공격자, 피해량, 경직과 태그를 묶은 `DamageEvent`와 이를 처리하는 `DamageReceiver`를 추가했다. 같은 `event_id`는 대상 하나에 한 번만 적용되고, 피격 후 0.50초 무적과 HP 0 사망이 공통 처리된다.

CP-203에서는 `WeaponDefinition`과 `SkillDefinition` 리소스로 검의 수치를 분리했다. 전방 표적에는 12→14→20 피해의 3연격을 자동 적용하고, 대상이 없는 상태가 0.90초 지속되면 콤보를 초기화한다. 돌진 베기는 3.5m 이동과 피해 35, 회전 베기는 주변 표적에 피해 20을 두 번 적용하며 각각 6초와 9초의 재사용 대기시간을 유지한다. 스킬별 취소 가능 시점 뒤에는 회피 입력이 공격을 중단한다.

CP-204에서는 활 프로필의 대상 사거리를 8m로 확장하되 화면 안 표적만 자동 선택한다. 기본 사격은 초속 14m의 실제 투사체로 0.75초마다 피해 14를 주며, 검 사거리 1.6m 안에서는 20퍼센트 감소한 피해 11을 적용한다. 관통 화살은 피해 36으로 최대 세 개체만 통과하고, 화살비는 화면 안 지정 범위의 각 표적에 피해 8을 여섯 번 적용한다. CP-204의 검·활 버튼은 비교를 위한 즉시 전환이며 0.50초 제한과 전환 상태 보존은 CP-205에서 완성한다.

CP-205에서는 전환 성공 후 0.50초 동안 반복 입력을 차단한다. 스킬이나 회피 중 들어온 전환 입력은 0.20초만 예약하며, 그 안에 행동이 끝나면 한 번 실행된다. 검과 활 컨트롤러는 비활성 상태에서도 기본 공격 대기시간과 각 스킬 재사용 대기시간을 계속 계산하므로 전환을 반복해 초기화할 수 없다. HUD에서 두 무기의 기본 공격 및 스킬 잔여 시간을 동시에 확인할 수 있다.

CP-206에서는 기본 공격 적중 시 4, 스킬 적중 시 8, 정확한 회피 시 12만큼 `새벽의 틈` 게이지를 획득한다. 게이지 100을 소모하면 3초 동안 `enemy_time_scaled` 그룹의 적과 적 투사체만 15퍼센트 속도로 느려진다. 전역 시간 배율을 사용하지 않아 플레이어 이동과 플레이어의 활 투사체는 항상 정상 속도를 유지한다. HUD 버튼의 원형 게이지와 상단 상태 줄에서 충전률, 남은 시간과 영향 대상을 확인할 수 있다.

CP-301에서는 체력 36의 풀잎 슬라임이 3m 이내에서 0.35초 경고 뒤 점프해 피해 8을 주고 착지 후 0.8초 빈틈을 만든다. 체력 30의 씨앗 포대는 4–7m 거리를 유지하며 1초 조준 경고 뒤 피해 7의 씨앗탄 세 발을 부채꼴로 발사하고, 검에 맞으면 뒤로 밀리며 1초 동안 사격하지 않는다. 체력 24의 바람 정령은 머리 높이를 유지하다 흰 직선 경고를 0.6초 표시한 뒤 피해 10의 돌진을 하고, 벽이나 빗나감 뒤 1.2초 멈춘다. 세 적의 현재 경고·행동·생존 수와 씨앗탄 수를 HUD에서 확인할 수 있다.

## 구현 내용

- Godot 4.7.2 stable 대상 프로젝트 생성
- 1920×1080 기준 가로 화면과 `canvas_items` 확장 설정
- 모바일 안전 영역을 화면에 표시
- Android 프레임 페이싱 활성화
- 60 FPS / 30 FPS 제한 전환
- 터치 포인터 ID, 좌표, 현재·최대 동시 터치 수 표시
- 세 영역 동시 입력 확인
- 마우스를 단일 터치로 변환해 데스크톱에서도 기본 동작 확인 가능
- GL Compatibility 렌더러 사용

## 환경 확인 결과

GitHub Actions에서 Godot 4.7.2, JDK 17과 Android SDK를 사용해 ARM64 디버그 APK 생성과 서명 검증까지 자동화했다. 실제 터치 감각과 포인터 유지 여부는 사용자 기기에서 확인한다.

1. 실제 기기 설치
2. 실제 기기에서 3개 이상의 멀티터치 확인
3. 30/60 FPS 체감 입력 지연 비교
4. 이동 패드를 유지한 채 모든 액션 버튼 입력 확인
5. 스킬 중 점프와 무기 전환 버퍼 확인
6. 최고 속도에서 입력 해제 후 감속 PASS 확인
7. 반대 방향 입력 시 방향 전환 PASS와 캐릭터 시선 확인

## CP-001/002 완료 조건

- Godot 4.7.2 Editor에서 오류 없이 프로젝트가 열린다.
- USB 디버깅 기기에 원클릭 배포된다.
- 가로 화면과 안전 영역이 정상 표시된다.
- 세 손가락을 동시에 눌렀을 때 서로 다른 포인터 ID 세 개가 유지된다.
- 20초 동안 드래그해도 터치가 임의로 사라지거나 남지 않는다.
- 30/60 FPS 전환에 따라 표시 FPS가 안정되고 입력이 한 프레임 이상 불필요하게 지연되지 않는다.

CP-301 실기기 검증을 통과하면 `CP-302 갑옷 멧돼지 정예`로 이동한다.
